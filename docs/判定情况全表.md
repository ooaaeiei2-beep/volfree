# volfree 判定情况全表

生成方式：构造 `Handle` / `Blocker` 组合后**直接调用 `volfree.assess()`**，把真实返回的
等级与理由打出来，不是读代码推断。装置见 `experiments/matrix.py`。

用途：判定逻辑的语义基准。凡是本表列出的格子，改动后必须逐格复跑；
复跑命令 `python3 experiments/matrix.py`，末行应打印「共 22 例，不符 0 例」。

> 状态：**2026-10-28 修复后**。此前版本记录的 5 行不符已全部消除，见第 7 节。

---

## 0. 判定链条

```
lsof 原始字段
  → Handle（7 个输入属性 → write_state 三态 → 4 个派生属性）
    → Blocker（6 个派生属性 + 身份判定）
      → assess()（10 条路径 + 1 条后置权限改写，先命中先返回）
        → 进程等级 NEVER / RISKY / CAUTION / SAFE
          → 卷级结论（建议）
            → 处置动作（SIGTERM / SIGKILL / eject / unmount）
```

---

## 1. 句柄层：输入属性

| 属性 | 取值 | 来源 | 备注 |
|---|---|---|---|
| `fd` | 数字 / `cwd` / `txt` / `ltx` / `mem` / `DEL` | lsof 字段 `f` | `txt` / `mem` = 映射文件 |
| `access` | `r` / `w` / `u` / `''`（空） | lsof 字段 `a` | **`txt` 恒为空**，不可信 |
| `ftype` | `REG` / `DIR` / `CHR` / `FIFO` / `unix` / `IPv4` / `KQUEUE` | lsof 字段 `t` | |
| `name` | 绝对路径 / 非绝对路径 | lsof 字段 `n` | 非绝对路径即伪句柄 |
| `exists` | `True` / `False` / `None` | `stat` 路径 | `None` = 不判定（伪句柄） |
| `link_count` | `0` / `≥1` / `None` | lsof 字段 `k` | exFAT 对已删除文件仍报 1 |
| `mapped_writable` | `True` / `False` / `None` | `proc_pidinfo(PROC_PIDREGIONPATHINFO)` 的 `VM_PROT_WRITE` 位 | **`None` = 未探测或探测失败，绝不等于「只读」** |

`mapped_writable` 只在 `is_mapping` 为真时才去探。探测失败（无 libproc、权限不足、
进程已退出）一律留 `None`。

## 2. 句柄层：派生属性

### 2.1 `is_deleted` = `link_count == 0` 或 `exists is False`

| link_count | exists | is_deleted | 含义 |
|---|---|---|---|
| 0 | True | **True** | 内核确认已 unlink |
| 0 | False | **True** | 两信号一致 |
| 1 | False | **True** | 只有路径信号（exFAT 的常态） |
| 1 | True | False | 正常文件 |
| 2 | True | False | 有硬链接 |
| None | False | **True** | 无 link count 时靠路径 |
| None | None | False | 伪句柄，不参与 |

### 2.2 `is_mapping` = `fd ∈ {txt, mem}` 且 `ftype == REG`

映射句柄单独识别出来，是为了走 `mapped_writable` 这条路补可写性。

### 2.3 `write_state` —— 三态，这是本表最关键的一列

| 句柄 | access | mapped_writable | write_state | 含义 |
|---|---|---|---|---|
| 普通 fd 只读 | `r` | — | `no` | 确定只读 |
| 普通 fd 只写 | `w` | — | `yes` | 确定可写 |
| 普通 fd 读写 | `u` | — | `yes` | 确定可写 |
| 普通 fd 空 access | `''` | — | `no` | 非映射却空 access，按只读处理 |
| 映射 可写 | `''` | `True` | **`yes`** | 保护位含 `VM_PROT_WRITE` |
| 映射 只读 | `''` | `False` | **`no`** | 保护位不含写位 |
| 映射 未知 | `''` | `None` | **`unknown`** | 没读到，**不是只读** |
| cwd | `''` | — | `no` | 目录句柄不写数据 |

三条派生布尔都从 `write_state` 走，**不再直接读 `access`**：

| 属性 | 定义 | 说明 |
|---|---|---|
| `is_writing` | `write_state != "no"` | **保守**：未知按可写处理，宁可误报不可漏报 |
| `is_certainly_read_only` | `write_state == "no"` | 只有明确读到「不可写」才算只读 |
| `is_pseudo` | `name` 不以 `/` 开头 | socket、管道、`->0x...` 不参与文件级判定 |

`unknown` 落在两者之间：既算「在写」，又不算「只读」。这个不对称是有意的——
它保证任何取不到保护位的场景都不会被误判成安全。

## 3. 进程层：6 个派生属性

| 属性 | 定义 | 注意 |
|---|---|---|
| `real_handles` | 非伪句柄 | 后续全部属性的分母 |
| `writing_handles` | `real_handles` 中 `is_writing` 的 | 含 `unknown` |
| `has_write` | `writing_handles` 非空 | |
| `all_writes_unlinked` | `writing_handles` 非空，且**全部** `is_deleted` | 降为 CAUTION 的唯一前提 |
| `has_uncertain_write` | 任一 `real_handles` 的 `write_state == "unknown"` | 触发 A2b |
| `has_unlinked_write` | 任一 `writing_handles` 已删除 | 仅用于文案细分，**不再决定等级** |
| `all_deleted` | `real_handles` 非空，且**全部** `is_deleted` | 空集时为 False |
| `only_read` | `real_handles` 非空，且**全部** `is_certainly_read_only` | 未知不算只读 |

## 4. 进程层：`assess()` 的 10 条路径 + 1 条后置改写（先命中先返回）

| 序 | 条件 | 等级 | 理由 |
|---|---|---|---|
| A1 | `pid ∈ {0, 1, 自身}` 或 `exe ∈ PROTECTED_EXECUTABLES` | **NEVER** | 系统核心进程或本工具自身，不可终止 |
| A2 | `has_write` 且 `all_writes_unlinked` | CAUTION | 正在写一个已被删除的文件；终止会放弃这次写入…（不会损坏其他文件） |
| A2b | `has_write` 且 `has_uncertain_write` | **RISKY** | 有句柄的读写状态无法确认（可能是内存映射写入），按最坏情况处理 |
| A3 | `has_write` | **RISKY** | 持有写入句柄，终止可能留下截断或半写的文件 |
| A4 | `all_deleted` | SAFE | 句柄指向的文件已删除且为只读，终止不会丢失任何数据 |
| A5 | `exe` 命中 `RESTARTABLE_APPEX_HINTS` | SAFE | 系统按需重启的预览/缩略图扩展，终止后自动重建 |
| A6 | `only_read` 且 `exe` 以 `SYSTEM_HELPER_HINTS` 开头 | CAUTION | 系统辅助进程持只读句柄，终止可能影响系统功能 |
| A7 | `only_read` 且有 `cwd` 句柄 | CAUTION | 工作目录位于该卷上，离开该目录或结束该终端即可释放 |
| A8 | `only_read` | CAUTION | 持只读句柄，终止可能丢失该程序未保存的界面状态 |
| A9 | 兜底 | CAUTION | 占用状态无法完全判定，建议先尝试正常退出该程序 |

**A1b（后置改写，不在上表的顺序里）**：`uid ≥ 0` 且 `uid ≠ 当前用户` 且**无写入** → **NEVER**，
理由「属于其他用户，本工具无权终止；需 root 权限处理」。它由 `_apply_uid_policy()` 在
`_assess_level()` 之后统一施加，目的是在 `send_signal` 抛 `EPERM` **之前**就把「不可为」说清楚。

刻意**不覆盖有写入的等级**：正在写的进程必须继续是 RISKY。若因为「反正杀不掉」把它改成
NEVER，界面会被读成「它不影响我拔盘」——而这正是产品要避免的误读。
`uid < 0`（取不到）时不猜，保持原判。

`PROTECTED_EXECUTABLES`：launchd、WindowServer、mds
`SYSTEM_HELPER_HINTS`：`/System/Library/`、`/usr/libexec/`、`/usr/sbin/`
`RESTARTABLE_APPEX_HINTS`：`.appex/`、`QuickLook`、`Thumbnail`、`Thumb`

**A2 必须在 A2b 之前**：全部可写句柄都无名时，即使其中有 `unknown`，也不存在会被截断的
有名字文件，CAUTION 成立。反过来若 A2b 在前，`映射无名·未知` 会被误升为 RISKY。

## 5. 进程层：22 种句柄组合的实跑结果

「应为」依据四格模型：**会不会损坏现存文件，只看是否存在「有名字的可写句柄」**；
文件已无名字且无写入 → 零损失；文件已无名字但有写入 → 丢这次写入，不丢别的。

| # | 进程持有的句柄 | has_w | all_unl | uncert | only_r | 等级 | 应为 | |
|---|---|---|---|---|---|---|---|---|
| 1 | 只读·有名字 | 否 | 否 | 否 | 是 | CAUTION | CAUTION | ✓ |
| 2 | 写入·有名字 | 是 | 否 | 否 | 否 | RISKY | RISKY | ✓ |
| 3 | 只读·无名字 | 否 | 否 | 否 | 是 | SAFE | SAFE | ✓ |
| 4 | 写入·无名字 | 是 | 是 | 否 | 否 | CAUTION | CAUTION | ✓ |
| 5 | 只读有名 + 只读无名 | 否 | 否 | 否 | 是 | CAUTION | CAUTION | ✓ |
| 6 | 写入有名 + 写入无名 | 是 | **否** | 否 | 否 | **RISKY** | RISKY | ✓ |
| 7 | 写入有名 + 只读无名 | 是 | 否 | 否 | 否 | RISKY | RISKY | ✓ |
| 8 | 只读有名 + 写入无名 | 是 | **是** | 否 | 否 | **CAUTION** | CAUTION | ✓ |
| 9 | 映射有名·可写 | 是 | 否 | 否 | 否 | **RISKY** | RISKY | ✓ |
| 10 | 映射有名·只读 | 否 | 否 | 否 | 是 | CAUTION | CAUTION | ✓ |
| 11 | 映射有名·未知 | 是 | 否 | **是** | 否 | **RISKY** | RISKY | ✓ |
| 12 | 映射无名·可写 | 是 | 是 | 否 | 否 | **CAUTION** | CAUTION | ✓ |
| 13 | 映射无名·只读 | 否 | 否 | 否 | 是 | SAFE | SAFE | ✓ |
| 14 | 映射无名·未知 | 是 | 是 | 是 | 否 | CAUTION | CAUTION | ✓ |
| 15 | 映射有名·可写 + 只读 fd | 是 | 否 | 否 | 否 | RISKY | RISKY | ✓ |
| 16 | 映射有名·只读 + 只读 fd | 否 | 否 | 否 | 是 | CAUTION | CAUTION | ✓ |
| 17 | 映射有名 + 写入 fd | 是 | 否 | 否 | 否 | RISKY | RISKY | ✓ |
| 18 | cwd 在卷上 | 否 | 否 | 否 | 是 | CAUTION | CAUTION | ✓ |
| 19 | 只有伪句柄（socket） | 否 | 否 | 否 | 否 | CAUTION | CAUTION | ✓ |
| 20 | 只读 + 系统辅助进程 | 否 | 否 | 否 | 是 | CAUTION | CAUTION | ✓ |
| 21 | 只读 + 可重启扩展 | 否 | 否 | 否 | 是 | SAFE | SAFE | ✓ |
| 22 | 写入 + 受保护进程 | 是 | 否 | 否 | 否 | NEVER | NEVER | ✓ |

**22 行相符，0 行不符。**

三行需要说明的语义：

- **第 5 行**：同时持有「有名字只读」和「无名字只读」→ CAUTION。`all_deleted` 为 False
  （还有有名字的），有名字的只读句柄按四格模型本就属 CAUTION，不能因为「其中一个是无名的」
  就降到 SAFE。
- **第 6 行**：有名字的可写文件**确实会被截断**，所以 `all_writes_unlinked` 必须为 False
  → RISKY。这正是 R3 修掉的那一格。
- **第 8 行**：有名字的那个**是只读的**，不存在会被截断的有名字文件；可写的只有一个已删除
  文件。所以 CAUTION 才对。**修复前本表把这一行的「应为」写成 RISKY，那是错的**——
  当时把「有名字的句柄」和「有名字的可写句柄」混为一谈了。R3 的规则同时纠正了代码和这张表。

## 6. 修复前后的真机对比

装置 `experiments/probe.py`，7 种写法 × APFS/exFAT，判的是真实进程、真实 lsof 输出。

| 写法 | 事实 | 修复前 | 修复后 |
|---|---|---|---|
| `write`（普通写入 fd） | 在变 | RISKY | RISKY |
| `mmap_keep`（映射 + fd 未关） | 在变 | RISKY | RISKY |
| `mmap_close`（映射在、fd 已关，有名字） | **在变** | **CAUTION** ✗ | **RISKY** ✓ |
| `pymmap_close`（Python mmap 模块） | 在变 | RISKY | RISKY |
| `mmap_ro`（只读映射） | 不变 | CAUTION | CAUTION |
| `mmap_ro_close`（只读映射 + fd 已关） | 不变 | CAUTION | CAUTION |
| `mmap_close_unlink`（映射 + fd 已关 + 已删除） | **在变** | **SAFE** ✗ | **CAUTION** ✓ |

两种文件系统结果一致。关键两行：

- `mmap_close` 从 CAUTION 升到 RISKY —— 名字还在，写入进行中，杀了就是半截文件；
- `mmap_close_unlink` 从 SAFE 升到 CAUTION —— 假绿消除。文件已无名，杀它只丢这一次写入，
  所以停在 CAUTION 而不是 RISKY。

`mmap_ro` / `mmap_ro_close` **没有被误升**，说明修复不是「一律当可写」的粗暴改法。

## 7. 三处缺陷：根因与修复

### R1 · 映射句柄的可写性丢失

lsof 为映射文件报的 `fd=txt` 条目，`access` 字段**恒为空串**，而旧代码的 `is_writing`
只认 `w` / `u`。于是任何 mmap 写入都被算成只读。

修复：新增 `mapped_writable`，用 `proc_pidinfo(PROC_PIDREGIONPATHINFO)` 遍历进程映射区，
取 `pri_protection` 的 `VM_PROT_WRITE` 位。实测与 `vmmap` 的 `rw-/rwx`、`r--/r-x` 逐字一致
（装置 `experiments/region_probe.py`）。

结构体 `proc_regionwithpathinfo` 实测 **1272 字节**；遍历末尾必然返回一次 `EINVAL(22)`，
属正常终止，不当错误处理。

### R2 · 「未知」被当成「只读」

旧 `only_read = all(not is_writing)`，空 access 使 `is_writing` 为假，该句柄就被算进「只读」。
`all_deleted` 判 SAFE 的理由文案直接写「且为只读」——但事实是**从来没读到过访问模式**。

这是 R1 之所以致命的机制：不是「判错了读写」，而是「没读到就当作只读」。

修复：把可写性拆成 `write_state` 三态，`is_writing` 与 `is_certainly_read_only` 分别从两端
取值，`unknown` 落在中间——既不算只读（挡住 SAFE），也触发 A2b 升 RISKY（挡住 CAUTION）。
即使 `proc_pidinfo` 整体不可用，也只是回到 RISKY，不会回到 SAFE。

### R3 · 混合场景被降级

旧 A2 的条件是 `has_unlinked_write`——只要**存在一个**无名可写句柄就为真，且它排在
`has_write` 之前。于是「既有有名字的可写文件、又有无名的临时文件」的进程被判 CAUTION，
理由还写着「不会损坏其他文件」，但它确实会损坏那个有名字的文件。

修复：判据从「存在」改为「全部」。新增 `all_writes_unlinked`，要求所有可写句柄都无名，
才允许降为 CAUTION。`has_unlinked_write` 保留，但只用于文案细分，不再决定等级。

## 8. 卷层：结论与动作

### 8.1 结论（`render_report`）

| 条件 | 输出 |
|---|---|
| 无占用 且 权限完整 | 可直接在访达推出 |
| 无占用 且 权限受限 | 先补齐权限再判断（`sudo` / 完全磁盘访问） |
| 有 SAFE | 可安全结束：名单 |
| 有 RISKY | 存在写入，勿强杀：名单 —— 请先在对应程序中保存并退出 |
| 无 RISKY | 执行 `volfree release "<卷>" --apply` |
| 有 RISKY | 待写入结束后再执行 release |
| 权限受限 | 以上仅为本用户可见的部分，系统进程可能另有占用 |

### 8.2 处置（`release_volume`）

| 等级 | 归属 | 动作 |
|---|---|---|
| SAFE | actionable | 询问 → 校验身份 → SIGTERM → 0.6s 后复核 |
| CAUTION | actionable | 同上 |
| RISKY | forbidden | 跳过，只打印 |
| NEVER | forbidden | 跳过，只打印 |
| 未退出 且 `--force` | — | 再询问 → SIGKILL |
| 未退出 且 无 `--force` | — | 提示「如需强制结束请加 --force」 |

处置后复核扫描，仍有句柄则提示「卸载可能失败」。

### 8.3 卸载动作

| 卷属性 | 动词 | 文案 |
|---|---|---|
| `removable` 或 `ejectable` 或 `external` | `diskutil eject` | 推出 |
| 三者皆假 | `diskutil unmount` | 卸载 |

| 结果 | 处理 |
|---|---|
| 成功 | 提示可拔线 |
| 超时（120s） | 提示手册说明最长需 1 分钟，不要强制 |
| `--force-unmount` 且仍有可写句柄 | **拒绝**，列出进程名 |
| `--force-unmount` 且无可写句柄 | 放行 |

拒绝强卸载的理由据 2026-10-28 实测重写：强卸载**不毁盘**（fsck exit 0、逐块完好），
真正的伤害是写入被立刻掐断（exFAT `ENXIO`、APFS `EIO`），丢的是**没写完的那部分**。

### 8.4 卷能力

| `link_count_reliable` | 含义 | 输出 |
|---|---|---|
| `None` | 未探测 | 无 |
| `True` | 曾见 `k==0` | 无 |
| `False` | 见「路径已消失但 `k>=1`」 | 告警：本卷不上报可靠 link count，改用路径校验 |

### 8.5 界面用的原子命令

界面的每个按钮都落到一条不提问的命令上，避免界面自己实现一遍判定：

| 界面动作 | 命令 | 等级拦截 |
|---|---|---|
| 轮询 / 首次加载 | `status --json` | — |
| 逐项「结束…」 | `end <pid> --volume <卷> --json` | NEVER 拒绝；RISKY 需 `--allow-risky` |
| 红态「仍要结束…」 | 同上 + `--allow-risky --force` | 用户已逐项确认，允许升级到 SIGKILL |
| 绿态主按钮 | `eject <卷> --json` | 存在可写句柄一律拒绝 |
| 黄态主按钮 | 逐个 `end` 完再 `eject` | 同左，失败原因逐条回显 |

`end` 与 `release` 的分工：`release` 是给人用的批量流程（含推出与逐项提问），
`end` 只结束一个进程、不碰挂载状态。两者共用 `verify_identity` / `send_signal`，
不另开一套判断。

## 9. 界面层：三态

| 态 | 触发条件 | 裁决 | 主按钮 | 详情入口 |
|---|---|---|---|---|
| 绿 | 无占用 | 可以拔了 | 推出 | 隐藏 |
| 黄·普通 | 有占用，无 RISKY，无无名可写 | 可以安全推出 | 安全结束并推出 | 查看 N 个程序 |

界面层代码未改动，三态与第 4 节等级的映射保持原样。

## 10. 无法判定 / 未验证的边界

| 项 | 现状 |
|---|---|
| 非 root 运行 | 只能看到本用户进程，`access_level=limited`，报告会标注 |
| 取保护位失败 | 回落到 `unknown` → RISKY，不会回落成 SAFE |
